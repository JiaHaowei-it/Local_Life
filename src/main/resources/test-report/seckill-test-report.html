03

被测业务分析

BUSINESS

接口 POST /voucher-order/seckill/{id}，核心判定顺序：

1. 查询秒杀券 getById(voucherId)
2. beginTime > now → 「秒杀尚未开始!」
3. endTime < now → 「秒杀已结束!」
4. stock < 1 → 「库存不足」
5. 取当前用户（UserHolder / ThreadLocal）
6. 获取分布式锁 tryLock("lock:order:{userId}") 失败 → 「不允许重复下单」
7. 事务 createVoucherOrder：一人一单校验 → 乐观锁扣库存（stock>0）→ 生成分布式 ID 插入订单
8. finally 释放锁（Lua 比对线程标识后删除）
机制实现作用
一人一单按 userId 的 Redis 分布式锁 + 事务内订单计数同用户并发串行，防重复下单
防超卖乐观锁 SET stock=stock-1 WHERE stock>0库存不出现负数
删锁原子性Lua 脚本比对线程标识后再 del防止误删他人锁
分布式 IDRedisIdWorker：时间戳左移 32 位 + 按天自增订单主键全局唯一、趋势递增
事务生效@EnableAspectJAutoProxy(exposeProxy) + AopContext扣库存与插单同事务原子

06

缺陷与风险记录

DEFECTS
高

BUG-01 · 券不存在时抛 NPE

getById 返回 null，voucher.getBeginTime() 空指针，未做空值兜底。

高

BUG-02 · 传普通券 id 抛 NPE

tb_seckill_voucher 无该主键 → getById 返回 null。

高

BUG-03 · 未登录访问抛 NPE

拦截器 setStatus(401) 后未 return false，请求仍放行，UserHolder 为 null。

中

RISK-04 · 结束时刻边界语义

endTime.isBefore(now) 在 now=endTime 时仍允许下单，需与业务确认。

中

RISK-05 · 缺少唯一约束兜底

(user_id, voucher_id) 未建唯一索引，依赖锁保障，锁失效时可能重复下单。

低

RISK-06 · 锁超时风险

锁超时 1200s，业务超时锁提前过期时极端并发下可能失效。

07

测试结论与建议

CONCLUSION

优惠券秒杀下单业务在当前实现下通过压力测试：防超卖与一人一单两项核心保证均验证有效，功能用例覆盖时间、库存、用户、锁、参数各维度分支。

  • 修复 BUG-01/02/03：对不存在的券、非秒杀券、未登录场景做空值兜底与正确拦截，避免 NPE。
  • 明确结束时刻边界语义：now=endTime 时是否允许下单需与业务确认。
  • 建议为 (user_id, voucher_id) 增加数据库唯一索引作为兜底。
  • 高并发吞吐优化方向：Redis 预扣减库存、异步消息队列削峰、库存原子 DECR；当前同步直连方案吞吐受连接池与行锁限制。
本报告数据来自 2026-09-30 实际执行结果；压测使用专用压测券，测试数据已清理，不影响原业务数据。
